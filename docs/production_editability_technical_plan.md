# 生产落地技术方案：评测流程可编辑与可信证据边界

## 目标

评测平台需要支持真实生产中的多场景、多模型、多版本任务迭代。用户在评测过程中可以修正输入、校准中间产物、重新生成测试集或重跑模型，但不能直接篡改对话轨迹、评分证据和最终得分。

## 可编辑边界

| 阶段 | 生产权限 | 原因 |
| --- | --- | --- |
| 评测模型 | 可编辑 | 生产中需要切换被测模型、Judge 模式和模型网关。 |
| 任务指令与待评测数据 | 可编辑 | 输入源必须支持不同履约场景和样本批次。 |
| 指令解析 | 可重新生成，可添加人工校准备注 | 解析结果可由业务专家复核，但不直接覆盖原始指令。 |
| Rubric | 可重新生成，可添加人工校准备注 | 评分标准需要可校准，权重和规则应保留版本记录。 |
| 测试场景 | 可重新生成，可选择/取消场景，可添加备注 | 评测覆盖面需要可控，场景选择会影响本次 run。 |
| 对话轨迹与评分结果 | 不可编辑，只能重跑 | 轨迹和分数是证据层，直接修改会破坏评测可信度。 |
| 最终报告 | 不可改分，可追加复核备注 | 报告分数来自系统评测，人工只能补充说明。 |

## 失效传播规则

当前端检测到上游内容被修改时，必须让下游产物失效，避免旧结果和新输入混用。

- 修改模型配置：当前模型配置需要重新保存；已运行结果和报告应视为过期。
- 修改任务指令或评测数据：指令解析、Rubric、测试场景、运行结果和报告全部失效。
- 重新生成指令解析：Rubric、测试场景、运行结果和报告失效。
- 重新生成 Rubric：测试场景、运行结果和报告失效。
- 重新生成测试场景或修改场景选择：运行结果和报告失效。
- 重跑评测：报告随新的轨迹和结果重新生成。

## MVP 实现策略

当前 MVP 采用前端状态机实现可编辑链路：

- `generatedSteps` 表示当前步骤结果是否已经生成。
- 用户修改输入时，调用失效传播逻辑清理当前及下游步骤状态。
- 中间产物页面提供“校准备注”和“重新生成当前结果”入口。
- 轨迹与结果页面只提供“重新运行评测”，不提供编辑分数或轨迹能力。
- 最终报告展示系统生成结果，保留 Markdown 报告预览。

## 后续生产扩展

生产系统建议将当前前端状态升级为后端版本化实体：

- `TaskSpecVersion`
- `RubricVersion`
- `ScenarioSuiteVersion`
- `RunVersion`
- `HumanReviewNote`

每次重新生成或人工校准都应产生新版本，并记录操作者、时间、来源输入和差异摘要。这样可以支持回归评测、审计追踪和跨业务线复用。
